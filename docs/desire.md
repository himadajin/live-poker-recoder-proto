# Live Poker Hand Recorder

## Purpose

ライブポーカー中に、プレイへの集中をできるだけ壊さず、後から補完なしで GTO Wizard に再現できる精度のハンド記録を残す。

このアプリは解析ツールではなく、合法的に観測できた客観情報を、スマホ縦画面で素早く、間違いにくく、修正しやすく記録するための道具にする。記録体験はフォーム入力ではなく、実卓を再現するゲーム風 UI と NLH の進行ルールに基づく状態機械を中心に設計する。

## Context

対象はライブの NLH キャッシュゲームに限定する。初版では 9max、固定ブラインド、ストラドル、アンティを扱い、PLO、トーナメント、特殊ゲームは扱わない。

ユーザーはプレイ中に自分で手入力する。カジノやポーカールーム側のハンド履歴サービスは前提にしない。後から入力する形式では記憶が落ちるため、プレイ中に記録できることが重要。

記録は分析、収支管理、統計、戦略助言を目的にしない。プレイ中に GTO 判断、推奨アクション、評価を出さない。ユーザーが合法的に手に入れた情報を記録し、後で他ツールで解析できる状態にすることに特化する。

UI はスマホ縦画面に最適化する。PC でも縦画面相当で使える程度ならよいが、初版の主対象はスマホ。PokerNow のように、卓、席、ポット、ボード、アクションボタンを持つゲーム風 UI を参考にする。

テーブルは常に 9 席固定レイアウトとして表示し、ユーザー視点に回転させない。実卓で見た座席配置とアプリ上の位置を一致させ、後で見返したときの記憶と対応しやすくする。ボタン位置はテーブル上を移動する。

ハンドごとに席、ブラインド、スタック、ボタンを毎回入力しない。アプリはセッション中のテーブル状態を持ち、各ハンド開始時点の状態をスナップショットする。カジノ/ルーム/レートごとのゲーム設定プリセットには、ブラインド、アンティ、ストラドル有無と基本額、チップ単位/入力ステップ、通貨表示など、店やレートで固定される情報を持たせる。セッションには、その日の席、プレイヤー、スタック、ボタン位置を持たせる。

ハンド中は NLH キャッシュで合法なアクションだけを入力できるようにする。アーリーフォールドは初版では扱わず、順番が来たときにフォールドしたことにする。ハンド間だけ、離着席、席の有効/無効、スタック補正を可能にする。ハンド中のプレイヤー出入りは非対応にして、状態機械を単純に保つ。

他プレイヤーのスタックはライブでは常に厳密に把握できない。自分のスタックはできるだけ正確に持ち、他プレイヤーは観測時点の概算スタックを持ち、以後のベットや勝敗で機械的に増減させる。オールインやチップカウントなどで正確値が分かったら補正する。データ上は exact と estimated を区別し、推定を真実のように扱わない。

カードは、自分の手札、ボード、ショーダウンや expose などで明確に公開/観測できた相手の手札だけを記録する。色だけ分かった、たぶん 6 か 9 のような曖昧な情報は記録対象にしない。見えていないカードは unknown のまま残す。

初版は全ハンド記録を強制しない。記録開始したハンドはできるだけ完全に追うが、記録しないハンドはスキップできる。スキップ時もテーブル状態が破綻しないよう、必要ならボタン移動やスタック補正だけ行えるようにする。

ハンド記録の主データは、集計済みの最終状態ではなく、時系列の構造化イベントログにする。そこから現在状態、ポット、スタック、Undo、将来のリプレイ、GTO Wizard 向け出力を生成する。

技術選定は React + Vite + TypeScript + Vitest を基本にする。UI は Tailwind CSS + shadcn/ui を使い、汎用部品の実装コストを下げる。ただし、テーブル本体、座席、カード、チップ、アクション入力など、このアプリ固有のゲーム風 UI は専用 React コンポーネントとして作る。

NLH の状態機械は UI ライブラリや状態機械ライブラリに寄せすぎず、まずは pure TypeScript のドメイン層として表現する。`applyEvent`、`getLegalActions`、`validateExport` のような UI 非依存の純粋関数を中心にし、React はそれを呼ぶ側にする。XState などの状態機械ライブラリは初版では必須にしない。

コード品質は ESLint + typescript-eslint + react-hooks + react-refresh、Prettier、TypeScript typecheck、Vitest を使って保つ。Tailwind を使うため、必要なら prettier-plugin-tailwindcss を使う。Playwright は CLI で完結するスマホ縦画面の代表 E2E に使うが、ポーカー状態機械の網羅は Vitest に寄せる。

保存は最小限にする。クラウド同期は作らない。完了済みハンドと設定は端末内に保存するが、アプリ再起動後の未完了ハンド完全復元は初版では保証しない。短時間の通信断に強い体験は望ましいが、復元保証を増やして仕様を膨らませない。

初版では主観メモ、解析、収支、統計、クラウド、リプレイを作らない。リプレイは将来追加したいが、初版ではイベントログ設計が将来のリプレイを妨げないことだけを考慮する。

## Direction

最初に作るべきものは、フォーム型の記録アプリではなく、ライブハンドの進行を追跡する簡易 PokerNow 風の記録 UI である。アプリはテーブル状態、ハンド状態、現在ストリート、次にアクションする席、合法アクション、必要コール額、最小レイズ、ポット、各プレイヤーのコミット額/残スタックを追跡し、今入力できるものだけを表示する。

入力体験では、毎回同じことを入力させないこと、今入れるべき情報だけを出すこと、間違いに早く気付けること、間違えたら最低限の操作で戻せることを重視する。初版から Undo、ハンド破棄、テーブル状態の手動補正は重要な機能として扱う。

ベット/レイズ額は追加額ではなく、そのストリートでそのプレイヤーが最終的に出している合計額として入力する。ライブでの “raise to 60” の `60` を入れる方式にする。call/check/fold はアプリが現在額から表示し、ユーザーは金額を入れない。ベット額 UI は戦略的なサイズ提案ではなく、実際に見えた/宣言された金額を素早く正確に入れるための最小額、all-in、テンキー/ステップ入力を中心にする。1/2 pot や pot のような戦略的ボタンは初版では不要。

オールインは、単に数字を入力するだけでなく、オールインしたという事実を記録できるようにする。具体額の細かいズレで状態が破綻しないよう、残スタックや観測情報と整合を取る。サイドポットはユーザーに細かく編集させず、アクション額とスタックから内部的に扱う。

ハンド終了時は、アクションログから計算したポットに対して勝者を選び、必要に応じて公開カードを入れ、例外時だけ手動補正する。初期状態と時系列アクションが正しければ、基本的にハンドは再現できるという考え方を中心にする。

検証は「完全/未完成」の重い概念ではなく、「エクスポート可能/要確認」の軽い判定に留める。GTO Wizard に補完なしで再現するために必要な客観情報だけを検証し、アプリが勝手に情報を補完しない。足りない情報、unknown、estimated はそのまま明示する。記録中は矛盾や入力漏れに早く気付けるようにし、ハンド終了時やエクスポート時にはどこが要確認かだけを示す。

エクスポートは初版では 1 ハンド単位を優先する。GTO Wizard への直接インポート連携を作り込むより、補完なしで手入力/貼り付け/参照できる正確なテキストまたは構造化フォーマットを出す。内部イベントログから GTO Wizard 向けの出力用データを生成する。

実装ではドメイン層のテストを厚くする。NLH 状態遷移、合法アクション、ポット/スタック、オールイン、Undo、エクスポート可能/要確認を Vitest で検証する。Playwright は iPhone 相当の縦画面で、セッション作成、ハンド開始、代表的なプリフロップからショーダウンまでの入力、Undo、1ハンドエクスポート、レイアウト破綻がないことを CLI で確認するために使う。Playwright で全ポーカーケースを網羅しない。

品質ゲートとして、`format check`、`lint`、`tsc --noEmit`、`vitest`、`build` をローカルで回せるようにする。E2E は初版から `test:e2e` として用意するが、安定するまでは通常の `check` とは分けてもよい。Husky、lint-staged、CI は初版必須にしない。

## Completion Conditions

- スマホ縦画面で、9席固定の実卓風テーブル UI が表示され、ユーザー視点に回転しない。
- カジノ/ルーム/レートごとのゲーム設定プリセットを作成でき、ブラインド、アンティ、ストラドル、チップ単位などを再利用できる。
- セッションがテーブル状態を持ち、席、プレイヤー、スタック、ボタン位置をハンド間で維持できる。
- ハンド開始時点のテーブル状態がスナップショットされ、以後のハンド記録が時系列の構造化イベントログとして残る。
- ハンド中は NLH キャッシュで合法なアクションだけが表示され、次に入力すべき情報だけに絞られている。
- fold/check/call/bet/raise/all-in、プリフロップからリバーまでのボード入力、ショーダウン/公開カード入力、勝者選択ができる。
- ベット/レイズ額は “to X” 方式で入力でき、call/check/fold はアプリが必要額や可否を表示する。
- オールインは金額だけでなくオールインの事実として記録でき、サイドポットや未コール額はイベントとスタックから内部的に扱われる。
- 自分のスタックと他プレイヤーのスタックを管理でき、他プレイヤーのスタックは exact/estimated を区別して扱える。
- ハンド間にだけ、離着席、席の有効/無効、スタック補正ができ、ハンド中のテーブル管理操作は出ない。
- 記録するハンドとスキップするハンドを選べ、スキップしてもセッションのテーブル状態が破綻しない。
- 入力ミスに対して、Undo、ハンド破棄、テーブル状態の手動補正ができる。
- アプリは勝手に不明情報を補完せず、unknown や estimated を明示したまま扱う。
- ハンドごとにエクスポート可能/要確認の軽い検証ができ、要確認の場合は不足や矛盾の場所が分かる。
- 1ハンド単位で、GTO Wizard に補完なしで再現するためのテキストまたは構造化フォーマットをエクスポートできる。
- 解析、収支管理、統計、戦略助言、クラウド同期、主観メモ、初版リプレイは実装されていない。
- 完了済みハンドと設定は端末内に保存されるが、未完了ハンドの再起動後完全復元は保証しない。
- React + Vite + TypeScript + Tailwind CSS + shadcn/ui でプロトタイプが構成されている。
- NLH の状態遷移は UI 非依存の pure TypeScript ドメイン層として実装され、主要ロジックが Vitest で検証されている。
- ESLint、typescript-eslint、Prettier、TypeScript typecheck、Vitest、build をローカル品質ゲートとして実行できる。
- Playwright のヘッドレス CLI E2E で、スマホ縦画面の代表的な入力フロー、Undo、1ハンドエクスポート、基本レイアウトが確認できる。
